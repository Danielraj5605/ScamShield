Privacy policy

Last updated 17 October 2026

ScamShield does not store the messages you check. It has no accounts, no cookies, no advertising and no analytics.

1. What ScamShield is

ScamShield is a student project built for the IBM Z Datathon 2026. It checks a text or WhatsApp message for signs of a scam. The project team operates it. This policy describes how the software in the public repository handles data.

2. Your message

  • The text you paste is sent to the server only to produce your result.
  • It is held in memory while the result is made, then discarded. It is not written to a database, a file or a log.
  • Links in your message are never opened or visited.
  • Messages longer than 2000 characters are rejected.

3. What the server records

The server writes a log line for each check. It contains a random request number, the time, the length of the message in characters, the risk level, the risk score and the processing time. It does not contain the message.

The web server's standard access log also records, for each page or request, the address of the device making it, the page requested and the response code. The software keeps the address in memory to limit how many checks one device can make per minute (120 by default). The project does not set an automatic deletion period for logs. They stay on the server until the operator deletes them.

4. The feedback buttons

The Yes and No buttons after a result are optional. If you press one, the server saves your answer, the risk level, the model version, the time, and a one-way hash of your message. The hash is created using a secret value held only on the server, so it cannot be used to recover your message. If the server has no secret value set, feedback is switched off and nothing is saved.

5. Written explanations from a language model

The "In plain words" text is written by ScamShield itself unless the operator has switched on a hosted language model. The footer of the home page shows which is in use.

When a hosted model is on, the server sends it a scrubbed copy of your message, in which links, email addresses, phone numbers, amounts and other numbers are replaced by placeholders, together with the warning signs that were found. The model's answer is checked before it is shown, and it can never change the risk level. The provider's own privacy terms then apply to what it receives. When no hosted model is on, nothing is sent to any outside service.

6. Cookies, storage and third parties

  • ScamShield sets no cookies and uses no browser storage.
  • The typefaces (Inter and IBM Plex Mono) are served from the same server. The pages make no requests to font services, analytics, advertising or social media.
  • The "Read aloud" button uses your browser's built-in speech feature. Depending on your browser and device, speech may be produced by an online service. ScamShield does not receive that audio or text.
  • Links to other sites, such as the source code on GitHub, are governed by those sites' own policies.

7. Security

ScamShield runs on an IBM LinuxONE virtual machine. The server limits the size and number of requests, shows results as plain text so that message content cannot run as code, and listens only on the machine itself unless the operator publishes it. If you use a public copy of ScamShield, check that the address begins with https.

8. Your choices and contact

You can use ScamShield without giving any personal information. Because your messages are not stored, there is nothing to delete or export. The saved feedback hash cannot be linked back to you or to your message.

For questions or concerns, open an issue at github.com/Danielraj5605/ScamShield/issues.

9. Changes to this policy

If the software changes how it handles data, this page will be updated and the date at the top will change.
