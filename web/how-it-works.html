How it works

ScamShield reads a message, runs several independent checks, and combines them into one risk level with reasons you can read.

What happens when you check a message

  1. The text is cleaned. Look-alike letters, hidden characters and tricks such as "hxxp" are undone, so a disguised word is read as the word it imitates.
  2. Four checks run side by side.
    • A wording model scores the language of the message (TF-IDF with logistic regression).
    • A second wording model, a small neural network, reads the raw characters. It was trained from scratch and copes better with odd spellings.
    • A link model scores the address of each link by its shape, for example a bank name inside an unrelated address. It never opens the link.
    • A set of 23 signals looks for known patterns, such as a request to share a one-time password, or a message about a bank that links to a different website. Twenty of these are warning signs and three are signs of a genuine notice.
  3. The results are combined. A small model learns how much to trust each check. It learned from each check's predictions on messages that check had not seen during its own training, so it does not simply trust a check that is over-confident.
  4. Safety rules apply. Five patterns always give a high-risk result, because missing them costs more than a false alarm: asking you to share an OTP or PIN, asking for your UPI PIN to receive money, a website imitating a bank, a claim of "digital arrest", and a request to install a remote-access app.
  5. You get the result. It includes the reasons, the words that raised the risk, the scam type if recognised, and what to do.

What ScamShield does not do

  • It never opens, visits or follows a link in your message.
  • It does not block, delete or reply to anything. It gives advice only.
  • It does not store your message. See the privacy policy.
  • It cannot prove a message is safe. A result of "no common warning signs" only means none were found.

Measured results

These numbers were measured on 17 October 2026 on the server this project runs on, an IBM LinuxONE virtual machine (s390x architecture, 3 processors, 8 GB of memory). The models were also trained there. Each test used messages the models had not seen.

Limits you should know about

  • On the public data, the combined system performs about the same as the simple wording model alone. Its advantage appears on the Indian-context set.
  • About 5% of genuine bank messages (7 of 132) were wrongly rated high risk on the main test. Under five other test splits the average was about 1%. Treat the real rate as a few percent, not zero.
  • The Indian-context messages were written by the team, and genuine message styles were added after mistakes were studied. That test is therefore not fully independent.
  • The system works in English only. Part of the public training data dates from about 2012.
  • New scam scripts with no familiar warning signs can be missed.

The full report, with confidence intervals, is in the project's public repository: reports/metrics_s390x.md.

Where it runs

The wording models, link models and combining model are trained, tested and run on an IBM LinuxONE virtual machine. The server has an on-chip AI accelerator, but ScamShield's models run on the ordinary processors and do not use it.

Optionally, a hosted language model can write the plain-words explanation. It only explains the result and cannot change it. If it is not switched on, ScamShield writes the explanation itself. The footer of the home page says which is in use.
